## Part 1 — Deployment Architecture

### Recommended setup: Azure Free Tier

This is the simplest option because `scripts/deploy-azure-free.ps1` already does 80% of the work.
You need nothing extra (no VPS, no IIS setup, no domain purchase). HTTPS is automatic.

```
STAGING TOPOLOGY
────────────────────────────────────────────────────────────────────
  Your phone (Android APK)
       │
       │ HTTPS
       ▼
  https://spareparts-api-XXXXX.azurewebsites.net   ← Azure App Service F1 (free)
       │                                              SpareParts.Api (.NET 8)
       │ private Azure link
       ▼
  spareparts-sql-XXXXX.database.windows.net        ← Azure SQL Serverless (free tier)
       │                                              SparePartsDb (staging)
  
  https://spareparts-web-XXXXX.azurewebsites.net   ← Azure App Service F1 (free)
       │                                              SpareParts.Web.React (React SPA)
       │ HTTPS API calls
       └──► https://spareparts-api-XXXXX.azurewebsites.net
────────────────────────────────────────────────────────────────────
```

**Why Azure and not DigitalOcean / VPS / Firebase?**
- The project already ships `scripts/deploy-azure-free.ps1` — it creates everything with one command
- Azure SQL Serverless has a free monthly limit that covers testing
- HTTPS certificates are automatic on `.azurewebsites.net` 
- SQL Server stays private (not exposed to the internet)
- You can shut everything down with `scripts/stop-free-host.ps1` to save cost

**For mobile distribution:**  
Use EAS Build (already configured in `eas.json`) with the `preview` profile — it builds a signed APK you download and sideload onto your phone. No Google Play needed.

**Subdomain structure:**
```
https://spareparts-api-XXXXX.azurewebsites.net     ← API
https://spareparts-web-XXXXX.azurewebsites.net     ← Web app
```
(XXXXX is a random 8-char suffix generated by the script to ensure uniqueness)

## Part 2 — Backend API Deployment

### Step 2.1 — Prerequisites (Windows machine)

Install these if not already present:

```powershell
# Azure CLI
winget install --id Microsoft.AzureCLI -e

# .NET 8 SDK
winget install --id Microsoft.DotNet.SDK.8 -e

# SqlPackage (needed to import your local DB to Azure SQL)
# Install via VS 2022 SQL tooling, or:
dotnet tool install -g microsoft.sqlpackage
```

### Step 2.2 — Create `appsettings.Staging.json` (do NOT commit secrets)

Create this file at `src/SpareParts.Api/appsettings.Staging.json`.
It is already git-ignored because secrets go in environment variables, not files.
This file only overrides non-secret settings:

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Warning",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "Cors": {
    "AllowedOrigins": [
      "https://spareparts-web-XXXXX.azurewebsites.net"
    ]
  }
}
```

> Replace `XXXXX` with the suffix generated during deployment.
> All secrets (JWT, connection string) are set as Azure App Service environment variables — never in files.

### Step 2.3 — Run the existing deploy script

Open PowerShell **as Administrator** and run:

```powershell
cd C:\path\to\SpareParts

.\scripts\deploy-azure-free.ps1 `
    -ResourceGroup "rg-spareparts-staging" `
    -Location "westeurope" `
    -PublicWebBaseUrl "https://spareparts-web-XXXXX.azurewebsites.net"
```

> The first run generates the suffix automatically. After the script completes it prints the real URL.
> If you don't know the web URL yet (deploying API first), omit `-PublicWebBaseUrl` and update CORS later.

**What the script does automatically:**
1. Creates Azure resource group
2. Creates Azure App Service Plan F1 (free)
3. Creates Azure App Service for the API with .NET 8 runtime
4. Creates Azure SQL logical server
5. Opens firewall for Azure services (not public internet)
6. Creates Azure SQL Database (Serverless, free tier, auto-pauses when idle)
7. Exports your local `SparePartsDb` as BACPAC and imports it into Azure SQL
8. Sets all environment variables on the App Service (connection string, JWT secret, CORS)
9. Publishes and deploys the API
10. Waits for health check to return `{ "status": "ok" }`
11. Writes `artifacts/azure-free/web-config.azure.js` with the correct API URL for the web app

### Step 2.4 — What the script sets as environment variables

The script injects these into Azure App Service (visible in Portal → Configuration → App Settings):

| Variable | Value |
|----------|-------|
| `ASPNETCORE_ENVIRONMENT` | `Production` |
| `ConnectionStrings__DefaultConnection` | Azure SQL connection string |
| `Jwt__Secret` | Auto-generated 64-char random base64 string |
| `Jwt__Issuer` | `SpareParts.Api` |
| `Jwt__Audience` | `SpareParts.Desktop` |
| `Cors__AllowedOrigins__0` | `http://localhost:5078` |
| `Cors__AllowedOrigins__1` | `http://127.0.0.1:5078` |
| `Cors__AllowedOrigins__2` | Your web app URL |

### Step 2.5 — Add mobile app origin to CORS after you know the web URL

The API also needs to allow your web app URL. After deployment:

```powershell
$rg = "rg-spareparts-staging"
$app = "spareparts-api-XXXXX"   # replace with your actual app name
$webUrl = "https://spareparts-web-XXXXX.azurewebsites.net"

az webapp config appsettings set `
    --resource-group $rg `
    --name $app `
    --settings "Cors__AllowedOrigins__2=$webUrl" `
    --output none
```

> The API does NOT need a CORS entry for the React Native mobile app.
> Mobile apps do not use browser CORS — they call the API directly with a Bearer token.

## Part 3 — Database Setup

### Step 3.1 — What the script does with the database

The deploy script automatically:
1. Uses `SqlPackage.exe` to export your local `SparePartsDb` as a `.bacpac` file
2. Imports that `.bacpac` into Azure SQL
3. On first API startup, `.NET` Dapper migrations run automatically (34 migrations via `SparePartsApiComposition.cs`)

### Step 3.2 — If you want to use ONLY safe test data (no customer data)

Instead of exporting your full local database, use the git-safe snapshot:

```powershell
# First: create an empty staging database locally for export
sqlcmd -S localhost -E -C -Q "CREATE DATABASE SparePartsDbStaging"

# Apply migrations by running the API pointed at the empty DB once:
# (set env var temporarily)
$env:ConnectionStrings__DefaultConnection = "Server=localhost;Database=SparePartsDbStaging;Trusted_Connection=True;TrustServerCertificate=True;"
dotnet run --project src/SpareParts.Api --no-build &
Start-Sleep 10
Stop-Process -Name "SpareParts.Api" -ErrorAction SilentlyContinue

# Then apply git-safe snapshot data (brands, parts, cars — no personal data)
cd database/git-safe-snapshot
sqlcmd -S localhost -d SparePartsDbStaging -E -C -i apply.sql

# Now export this clean staging database
# (pass -LocalConnectionString to the deploy script)
.\scripts\deploy-azure-free.ps1 `
    -LocalConnectionString "Server=localhost;Database=SparePartsDbStaging;Trusted_Connection=True;TrustServerCertificate=True;" `
    -ResourceGroup "rg-spareparts-staging"
```

### Step 3.3 — Security: SQL Server is NOT public

Azure SQL with the `AllowAzureServices` firewall rule means:
- Only services running inside Azure (your App Service) can reach the database
- Your phone, laptop, or any external IP cannot connect directly
- This is correct and safe for staging

### Step 3.4 — Backup before any deployment

```powershell
# Export production database to BACPAC before any changes
$prod_conn = "Server=YOUR_PROD_SERVER;Database=SparePartsDb;..."
SqlPackage /Action:Export /SourceConnectionString:$prod_conn /TargetFile:backup-$(Get-Date -Format 'yyyyMMdd-HHmm').bacpac
```

### Step 3.5 — Rollback database

```powershell
# Import a previous BACPAC to restore the staging database
SqlPackage /Action:Import `
    /SourceFile:backup-20260601-1430.bacpac `
    /TargetConnectionString:"Server=tcp:spareparts-sql-XXXXX.database.windows.net,1433;Initial Catalog=SparePartsDb;User ID=spadmin;Password=...;Encrypt=True;"
```

## Part 4 — React Web App Deployment

### How the web app gets its API URL

The file `src/SpareParts.Web.React/wwwroot/config.js` controls the API URL:

```javascript
window.SparePartsWebConfig = {
  defaultApiBaseUrl: "http://localhost:5000",   // ← change this for staging
  googleClientId: "",
  facebookAppId: ""
};
```

This file is loaded before React starts. The mobile app uses `app-config.js` which reads `process.env.EXPO_PUBLIC_API_BASE_URL`.

### Step 4.1 — Create the staging config file

After running the API deploy script, it writes `artifacts/azure-free/web-config.azure.js`.
That file already has the correct URL. Copy its content to overwrite `wwwroot/config.js`:

```powershell
# After deploy script completes:
Copy-Item artifacts/azure-free/web-config.azure.js `
    src/SpareParts.Web.React/wwwroot/config.js
```

Result in `config.js`:
```javascript
window.SparePartsWebConfig = {
  defaultApiBaseUrl: "https://spareparts-api-XXXXX.azurewebsites.net",
  googleClientId: "",
  facebookAppId: ""
};
```

> **Important:** Do NOT commit this change if the URL contains a temporary staging URL.
> Keep `config.js` pointing to `localhost` in git; apply the swap at build/deploy time.

### Step 4.2 — Publish the web app to a new Azure App Service

```powershell
$rg   = "rg-spareparts-staging"
$plan = "spareparts-free-plan"       # reuse the same F1 plan (supports multiple apps)
$webApp = "spareparts-web-XXXXX"     # use the same XXXXX suffix as your API app

# Create the web app (only once)
az webapp create `
    --resource-group $rg `
    --plan $plan `
    --name $webApp `
    --runtime "DOTNETCORE:8.0" `
    --output none

# Set environment
az webapp config appsettings set `
    --resource-group $rg `
    --name $webApp `
    --settings "ASPNETCORE_ENVIRONMENT=Production" `
    --output none

# Build and publish
dotnet publish src/SpareParts.Web.React/SpareParts.Web.React.csproj `
    -c Release -o artifacts/web-publish

# Zip and deploy
Compress-Archive -Path artifacts/web-publish/* -DestinationPath artifacts/web.zip -Force
az webapp deploy `
    --resource-group $rg `
    --name $webApp `
    --src-path artifacts/web.zip `
    --type zip `
    --restart true
```

### Step 4.3 — React routing: 404 on page refresh

The web app already handles this correctly. `Program.cs` contains:
```csharp
app.MapFallbackToFile("index.html");
```
This means every unknown path returns `index.html`, which lets React Router handle navigation.
No extra IIS `web.config` rewrite rules are needed.

### Step 4.4 — Verify the web app

```powershell
# Health check
curl https://spareparts-web-XXXXX.azurewebsites.net/health
# Expected: {"service":"SpareParts.Web.React","status":"ok",...}

# Open in browser
Start-Process "https://spareparts-web-XXXXX.azurewebsites.net"
```

### Step 4.5 — Confirm the web app is calling the online API

Open browser DevTools → Network tab → reload the page → find any API call.
The request URL should start with `https://spareparts-api-XXXXX.azurewebsites.net`, NOT `localhost`.

If you see `localhost` in the request URL, `config.js` was not updated. Repeat Step 4.1.

### Step 4.6 — Update CORS on the API to allow the web app origin

After the web app is deployed, run:

```powershell
az webapp config appsettings set `
    --resource-group rg-spareparts-staging `
    --name spareparts-api-XXXXX `
    --settings "Cors__AllowedOrigins__2=https://spareparts-web-XXXXX.azurewebsites.net" `
    --output none

az webapp restart --resource-group rg-spareparts-staging --name spareparts-api-XXXXX
```

## Part 5 — React Native Mobile App Configuration

### Where the API URL is set

**File:** `src/SpareParts.Mobile.ReactNative/src/core/app-config.js` — line 30:

```javascript
const defaultApiBaseUrl =
  process.env.EXPO_PUBLIC_API_BASE_URL ||
  (Platform.OS === "android" ? "http://10.0.2.2:5000" : "http://localhost:5000");
```

The app reads `EXPO_PUBLIC_API_BASE_URL` from the `.env` file at build time.
If the env var is not set, it falls back to `10.0.2.2:5000` (Android emulator) or `localhost:5000`.
**For a real phone on staging, the env var MUST be set to the Azure URL.**

### Step 5.1 — Create `.env` for staging

```powershell
cd src/SpareParts.Mobile.ReactNative

# Copy the template
Copy-Item .env.example .env
```

Edit `.env`:
```
EXPO_PUBLIC_API_BASE_URL=https://spareparts-api-XXXXX.azurewebsites.net
EXPO_PUBLIC_GOOGLE_CLIENT_ID=
EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID=
EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID=
EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID=
EXPO_PUBLIC_FACEBOOK_APP_ID=
```

> Replace `XXXXX` with your actual suffix from the deploy script output.
> `.env` is already git-ignored. Do NOT commit it.

### Step 5.2 — Android network permissions (already configured by Expo)

Expo handles `AndroidManifest.xml` permissions automatically.
Because your API is on HTTPS (`azurewebsites.net`), there is NO cleartext HTTP issue.
If you ever test against HTTP during early development, add this to `app.json`:

```json
"android": {
  "usesCleartextTraffic": true
}
```

**Do NOT use this in the final staging build.** HTTPS is already working.

### Step 5.3 — Verify the URL is set correctly before building

```powershell

# Should show: EXPO_PUBLIC_API_BASE_URL=https://spareparts-api-XXXXX.azurewebsites.net
```

Also confirm there is NO `localhost`, `127.0.0.1`, or `10.0.2.2` in the `.env` file.

## Part 10 — Troubleshooting

### API works locally but not online

**Symptom:** 500 or connection refused on Azure, works on localhost  
**Cause 1:** Database connection string wrong  
```powershell
az webapp config connection-string list --resource-group rg-spareparts-staging --name spareparts-api-XXXXX
# Verify DefaultConnection is set and points to Azure SQL
```
**Cause 2:** JWT Secret is the placeholder  
```powershell
az webapp config appsettings list --resource-group rg-spareparts-staging --name spareparts-api-XXXXX | grep Jwt
# Secret must NOT be "CHANGE_ME_USE_ENV_OR_USER_SECRETS"
```
**Cause 3:** App Service cold start (F1 tier goes to sleep)  
Call `/api/health` twice — first call wakes it up.

---

### CORS errors in browser

**Symptom:** Browser console shows `Access-Control-Allow-Origin` error  
**Fix:**
```powershell
# Add your web app URL to CORS
az webapp config appsettings set `
```

### Android network error (cleartext HTTP)

**Symptom:** App crashes or fails on HTTP URL  
**Cause:** Android 9+ blocks cleartext HTTP by default  
**Fix:** Use HTTPS. Your staging URL is already HTTPS (`azurewebsites.net`). This should not occur.

### JWT token invalid

**Symptom:** Login succeeds but subsequent API calls return 401  
**Cause 1:** `Jwt__Issuer` or `Jwt__Audience` mismatch between API and mobile app  
The API expects `Jwt__Issuer=SpareParts.Api` and `Jwt__Audience=SpareParts.Desktop`.
**Fix:** Check App Service settings match these values exactly.

**Cause 2:** JWT secret changed between deploys (tokens issued before are now invalid)  
**Fix:** Users must log in again after a deployment that changes `Jwt__Secret`.

### Image upload not working

**Symptom:** Photo upload returns 413 or fails silently  
**Fix 1:** Azure App Service has a default max request size of 28 MB.
For larger uploads, add to `web.config` in the publish output:
```xml
<system.webServer>
  <security>
    <requestFiltering>
      <requestLimits maxAllowedContentLength="52428800" />
    </requestFiltering>
  </security>
</system.webServer>
```
**Fix 2:** Check the upload folder path in `appsettings.json`. On Azure, use `D:\home\site\wwwroot\uploads\` or Azure Blob Storage.
